# ScummVM hybrid core for MiSTer (ScummVM)

@hybrid/CLAUDE.md

## This core

- Name everywhere: `ScummVM` (the engine: core, folders `games/dnk/ScummVM/` and `logs/dnk/ScummVM/`, `_Other/dnk/dnk-ScummVM_*.rbf`, release), `scummvm` (game submodule, binary in `build/`, log, lock). The games and their menu entries (`_Other/dnk-<title>.mgl`): `package/games.txt` (in the zip as `games/dnk/ScummVM/games.txt`, from which the database's build makes the launcher's catalogue).
- The game is the `scummvm/` submodule, branch `mister`. Its MiSTer code is behind the `MISTER_HYBRID` build option.
- Build: `./build.sh` (game), `./core/build_core.sh` (FPGA), `./package.sh` (zip in `dist/`), `MISTER=root@<address> tools/deploy.sh`.
- Release: the zip in `releases/`. Players get it once it is published to the database, only when Danik asks: `hybrid/launcher/distribution.py publish ~/dnk_Distribution_MiSTer releases/ScummVM_YYYYMMDD.zip` (the rule in `hybrid/CLAUDE.md`).
- Try a build on the MiSTer without installing it: `MISTER=root@<address> tools/test_on_mister.sh <id>|list|nodata|log|stop` (the rule in `hybrid/CLAUDE.md`).
- Lines marked `GAME:` in the scripts and `TODO` in the READMEs are the places the template left for this game.

## Decisions (Danik, 2026-10-24)

- **One menu entry, ScummVM's own launcher.** `package/games.txt` has the one line `ScummVM|ScummVM`; no set names, no curated games, no per-game MGLs. Players copy each game's folder into `games/dnk/ScummVM/` (or its USB copy) and add it with ScummVM's *Add Game* / *Mass Add*; the browser starts in `DATADIR`. So the missing-data rule has nothing to check: an empty launcher is the start, and the README says where games go. OSD settings and button mappings are the core's (one `ScummVM.CFG`); per-game settings are ScummVM's own (`scummvm.ini` in `DATADIR`, saves there too).
- **Source**: ScummVM v2026.4.0 (GPL-3.0-or-later). For now a local clone; the fork `ItsDanik/scummvm` (branch `mister`) and `ItsDanik/ScummVM_MiSTer` are made only when Danik says so.
- **Engines**: every 2D engine that is on by default and needs no OpenGL, built into the one binary (69 MB unstripped; Linux maps its pages as they are used), without the 3D ones and the heavy FMV or bigger-than-640x480 ones (`ENGINES_OFF` in `build.sh`: Zork Nemesis / ZGI, Blade Runner, Riven, Titanic, Myst 3, Broken Sword 2.5, Wintermute, Nancy Drew, ...). Dynamic plugins only if memory or start time turn out to need them. Plus `grim` (Grim Fandango) with its TinyGL software renderer, as an early benchmark: if it cannot hold a usable rate at 640x480i, say so to Danik before shipping it. And `monkey4` (Escape from Monkey Island, the same engine and renderer; Danik, 2026-10-27), not yet tried on the MiSTer. Parser / keyboard games (AGI, SCI0, Glk) are built in and run from the launcher; the README says they need a keyboard.
- **Video**: the window is the game's size, 1x, no scaler, no aspect correction. 320x200 games in 320x200; 640x480 in 640x480i, 640x400 in 640x400i; other sizes centred in the smallest mode they fit. ScummVM's GUI (launcher, Global Main Menu) at the game's resolution: lowres layout at 320x200, no mode switch when it opens. The launcher (no game running) is 320x200 by default, or 640x480i with ScummVM's highres layout by the OSD's *Launcher* line (Danik, 2026-10-25; `MisterGraphicsManager::initSize()` gives the launcher that size, and the switch is live while the launcher shows, else at the return to it). **No 240-line mode and no HUD lines**: the games' backgrounds and verb bars are fixed 200-line art (and the hires games 480 lines already), so nothing can fill 240 lines; `HUD_EDGES` none.
- **Backend**: `backends/platform/sdl/mister/` (`--host=mister`, or `--backend=mister` for the PC build; `MISTER_HYBRID`) on top of ScummVM's SDL/POSIX backend and `hybrid/sdl2`: `MisterGraphicsManager` makes the SDL window the game's size and draws into its RGB565 surface (no renderer), the cursor drawn in, CLUT8 converted (INDEX8 later as an optimisation); frames paced by `SDL_MISTER_VSYNC=1`. Data files (themes, engine data, virtual keyboard) in `data/` next to the program.
- **Music**: `MIDI_SYNTH` 1. *Music* = MIDI: General MIDI to the synthesizer (ScummVM's MT-32-to-GM mapping where a game has MT-32 music only); native MT-32 to an MT32-pi that is on in MT-32 mode. *Music* = FM chip: AdLib through a new OPL type writing `MH_FMWrite()` from a silent mixer stream (exact audio frames); OPL3 / dual OPL2 games fall back to DOSBox's OPL on the ARM. The MIDI driver is a `MidiDriver_Emulated` (exact `ahead`), keeps every channel's state to send again after `MH_MidiSynthChanged()`, and holds a song's start back by `MH_MidiBacklog()`. **Exception to the framework's rule**: the MIDI / FM switch takes effect at the next game start (engines pick their driver once); the Pi / synthesizer switch is live. No Munt.
- **Controls** (`J1`): stick and d-pad move the pointer (accelerating); A left click, B right click, X Esc (skip cutscene), Y `.` (skip line), L held slow pointer, R F5 (game's menu), Select virtual keyboard, Start Global Main Menu (Ctrl+F5). *Menu OK* / *Menu Back* are Enter / Esc in ScummVM's GUI. An engine's own pad keymap (Grim's and EMI's tank controls) wins while it runs. No rumble, triggers or stick clicks.
- **OSD game options** (from bit 24): *Pointer Speed*, *Launcher* (bit 34: 320x200 / 640x480), *Speech Volume*, *Subtitles* (Game default / Speech only / Subtitles only / Both, over every game's setting); *Sound Volume* / *Music Volume* are ScummVM's SFX and music volumes.
- **Cheats page**: *Fast Mode* Off / Fast / Turbo (SCUMM's Ctrl+F / Ctrl+G), greyed out (`MH_SetMenuMask()`) while another engine runs. Nothing else: the engines' other cheats are debugger commands with arguments.
- **Game icons** (Danik, 2026-10-25): every pack of ScummVM's icons (downloads.scummvm.org `frs/icons/`, 12 packs, 375 MB; GPL-2.0, scummvm-icons' LICENSE and AUTHORS next to them), merged into one pack by `tools/make_icons.py` (the newest pack's icon of a game wins, as in ScummVM; 752 icons; the newest pack's `games.xml`, `companies.xml`, `series.xml`, `engines.xml` too, which *Group by* Publisher / Series / Year and the artwork view read), each icon made in the sizes the launcher draws it at, so ScummVM only decodes it (the 512x512 icons made the launcher's start slow and its scrolling jerky on the MiSTer; with them made for the size it starts at once): `icons/` 99x99 (the grid at 4 a row in 640x480, inside the margin for CRTs), `icons143/` (3 a row), `icons236/` (the artwork view, JPEG on the theme's background); 61 MB, stored. The grid takes `icons<size>/` where its thumbnails have that size, else `icons/` scaled, and loads nothing before its layout gives the size (ScummVM decoded every visible icon a first time at size 0; `MISTER_HYBRID` in `gui/widgets/grid.cpp`). Palette and grey icons, which the grid skipped, are converted. **At least 3 icons a row** (Danik: "let's make it fast", then 3): the launcher's slider starts at 3 (`gui/launcher.cpp`, `MISTER_HYBRID`), and the backend raises a smaller `grid_items_per_row`. `tools/icons.sh` fetches the packs at pinned SHA-256 sums into `build/icons/` and makes the merged pack when it, `make_icons.py` or `make_theme.py` (the artwork's size and background) changes (`package.sh` runs it; never committed); it goes to `games/dnk/ScummVM/icons/`, the backend's `iconspath` (`getDefaultIconsPath()`, not `$HOME/.cache`). ScummVM has the grid only in its high resolution layout, so the icons show with *Launcher* at 640x480, at 320x200 it is the list.
- **Artwork view** (Danik, 2026-10-25, a third launcher view beside ScummVM's list and grid; **the default view**, written into `scummvm.ini` when it has none, as ScummVM reads it from there alone; a `scummvm.ini` from before keeps the view it has): the list on the left, on the right the selected game's icon at 236x236 (as big as fits under the logo and inside the margin) with its details under it: the title (`games.xml`'s, else the entry's description), publisher and year, series, engine, and platform, language and variant of the copy (`scummvm.ini`); each line only if known. Above, the logo 64 lines high (`logo_art.bmp`; Danik: the in-game menu's small one was too small), the search over the grouping and the help beside it; the list view's buttons in two rows below, the version between the views' buttons and the last ones. `LauncherArt` in `gui/launcher.cpp` (`MISTER_HYBRID`; a `LauncherSimple` whose widgets are named after its dialog), `gui_launcher_chooser=art`, its button (`art.bmp`, drawn in `make_theme.py`) next to the list's and the grid's. Only our theme has its layout (`LauncherArt` and `Globals.LauncherArtSupported` in its high resolution layout, `make_theme.py`; `ART_SIZE` there is the size `make_icons.py` makes the icons in); other themes and 320x200 show the list. The launcher goes back to the view picked when the layout has it again (the OSD's *Launcher* switched back to 640x480; ScummVM stayed in the list).
- **Margin for CRTs** (Danik, 2026-10-25): ScummVM's GUI keeps 10 pixels from the screen's edges at 640x400 / 640x480 and 5 at 320x200 (the same width on the screen), with every theme: the backend's safe area (`getSafeOverlayArea()` in `mister-graphics.cpp`, ScummVM's own mechanism for phone notches), which every dialog, popup and message keeps inside; the background of a dialog that fills the screen still reaches the edges, dialogs of their own size are moved inside. The layouts are still picked by the whole size (`MISTER_HYBRID` in `gui/gui-manager.cpp`: by the safe area 640x400 would get the low resolution layout and 320x200 a scale of 0.95). `tools/theme_preview.sh` (the installed ScummVM) shows the theme without it; the PC build with `fakecore` shows it.
- **Logo**: `package/logos/ScummVM.png` rendered from ScummVM's `gui/themes/common-svg/logo.svg` (440 wide, bottom-aligned).
- **GUI theme** (Danik, 2026-10-25, picked from prototypes): our own, "MiSTer Hybrid" (`misterhybrid.zip` in `data/`), the default (`gui_theme` in the backend; the others stay in Options > GUI). Made by `tools/make_theme.py` (into `build/theme/`; `package.sh` runs it): the purple screen's palette ("Wall": background `#7F30A0`, dark panels, the message bar's pink `#DF51AF` for the selection), Cozette 6x13 at every size for English (ScummVM allows a bitmap font only for its own language; translations get its TTFs), flat shapes (corners 1 at 320x200, 2 at 640x400 / 640x480; shadows and two-line borders only there), ScummVM's logo in pink and lavender with the MiSTer logo beside it (640x400 / 640x480 only), a white pointer with a dark outline, 11x16 at every resolution (Danik: the 22x32 one at 640x480 was too big; on a CRT at 480i its one-line outline does not flicker, Danik 2026-10-25), ScummVM's common layouts from the submodule with two changes: the game in grey behind the in-game menu (`shading = 'luminance'`), and the artwork view (below). ScummVM's bitmap-font scaler crashes on Cozette (SIGSEGV in `BdfFont::scaleFont`), so the backend defaults `gui_disable_fixed_font_scaling` to true. The theme is written into `scummvm.ini` when it has none (ScummVM's GUI registers its own default over the backend's), and the zip carries ScummVM's cache of the font (`cozette.fcc`, the same bytes as ScummVM writes): without it ScummVM reads the BDF at every start and writes the cache into `DATADIR`. Preview on the PC: `tools/theme_preview.sh <folder or zip> [low|400|480] [--start <id>] [--shot out.png ...]` (the installed flatpak, 1x SurfaceSdl as the MiSTer draws).

## Status (2026-10-25)

- Tested on the PC with `fakecore` (PC build, `./build.sh host`): the start and logo, ScummVM's launcher at 320x200, Lure of the Temptress at 320x200, the Fate of Atlantis demo with FM music (the core's chip) and with MIDI music (the synthesizer, GeneralUser GS), the pointer on the d-pad, Start (Global Main Menu) and Menu Back (closes it), the OSD's Fast Mode (Turbo). Free games for tests: downloads.scummvm.org (`frs/extras`, `frs/demos`), never committed.
- Danik installed the 2026-10-25 build on the MiSTer and found Grim Fandango below 10 fps. Still to do there: `tools/test_on_mister.sh` (`ScummVM`, `list`, `nodata`), Menu OK / Back on buttons with actions, the MT32-pi, music volume on the FM chip and the synthesizer (ScummVM applies *Music Volume* through the engines' own MIDI volume; check it reaches both), the `DRAW_AHEAD` benchmark of the framework rule (ScummVM paces with `SDL_MISTER_VSYNC`, no `MH_PresentAtField()` yet).
- **Grim Fandango on the MiSTer** (2026-10-25, Windows CD, Manny's office, 640x480i): was 5.7 to 9.5 fps (TinyGL's dirty rectangles on: 92 to 143ms a frame to draw once anything moved). Now about 21 fps standing, 14 to 19 walking, 13 with Manny filling a third of the screen. What did it, all measured on the MiSTer with `MISTER_PROF` (below): `dirtyrects` off by default (`mister.cpp`); textures point sampled, as the original's software renderer (`MISTER_HYBRID` in `engines/grim/gfx_tinygl.cpp`; bilinear filtering was most of Manny's time); in TinyGL (`graphics/tinygl/`, for every platform): an opaque colour-keyed image kept in the frame buffer's format, a fast textured span for RGB565 with 32-bit textures (`putTexturedSpanFast()`: z test, nearest texel, Gouraud, alpha test; compared span by span with the generic code, 5.7 million spans, none different), the stencil-only fill of Grim's shadows as a `memset`, a clear left out where blits overwrite it, and the frame's first draw calls (the base: background, z buffer image, the room's parts in front) drawn again only where the last frame drew over them (`presentBufferSimple()`; whole frames drawn both ways and compared, none different); in the backend: the window surface is the library's buffer (`SDL_MISTER_DIRECT`), ScummVM's `_tmpscreen` copy skipped, and only what changed in the last two frames copied (`MISTER_HYBRID` in `surfacesdl-graphics.cpp`; the shown buffer compared with ScummVM's screen, 1300 frames, none different). Left: the textured span itself (about 30% of a walking frame, bound by instructions; ARM instead of Thumb-2 made no clear difference), TinyGL's command side (about 15%), the shadow pass with the stencil test (about 6%). `grim` stays: Danik decides whether this is usable. Escape from Monkey Island (`monkey4`, 2026-10-27) gets all of it but the clear left out (its background is tiles; the clear is in the base anyway), and its 24-bit textures are made 32-bit (`MISTER_HYBRID` in `createTexture()`) so its opaque faces take the fast span; faces with blending (32-bit textures with alpha, EMI turns it on for them) still take the generic one. Not yet measured: `MISTER_PROF` in a room with characters decides whether a blended fast span is worth it.
- Development tools: `MISTER_PROF=<file>` (`backends/platform/sdl/mister/mister-prof.cpp`) samples where the time goes on the MiSTer (which has no `perf`) and prints the frames shown per second; `tools/prof.py` makes the table with the unstripped binary's `nm` (libc on the MiSTer is dynamic and stripped: its time shows as one line).
- The theme: checked on the PC at 320x200, 640x400 and 640x480 (launcher, options, popups, sliders, the in-game menu over Lure); not yet on a CRT (Cozette's one-line strokes at 480i), nor the in-game menu's small logo (needs a 640x480 game).
- Core: fitter `SEED 2` in `core/ScummVM.qsf` (2026-10-25: seed 1 missed the MIDI synthesizer's 100 MHz clock by 0.026 ns after a one-line change; seed 2 +0.043).
- README.md / NOTES.md: still the template's, the last step after testing.
